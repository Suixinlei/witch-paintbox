# 状态面板人设图

角色卡状态面板的肖像位读取卡内 `additionalAssets`（`{{raw::名称}}`），与画匣保存的人设图是两份。卡内缺资源条目、缺 `<img>` 或缺显示规则时只剩占位图，画匣换图后卡内也不会跟随。插件 2.5.8 起把画匣人设图自动盖到肖像位上，角色卡本身不改。

## 数据

`POST /v1/risu/portraits`（Risu 专用令牌）按 `cardId` 返回本卡带人设图的人物：`id`、`name`、`aliases`，以及各自一张缩略图。缩略图由服务按原图生成，长边不超过 640×960，WebP 编码，按原图内容缓存，服务启动后在后台预编一遍；无法解码的图跳过，不影响其余人物。

请求带上 `revision` 且资料未变时，服务只回 `{ revision, unchanged: true }`，不重传图片。`revision` 是 Risu 资料的整体版本，任一张卡或偏好保存后都会变化。

管理台「Risu 全局自动配图」中的「状态面板肖像取用画匣人设图」关闭后，接口返回空列表。

## 匹配

消息里每个 `<statusData>c|…varId:X…</statusData>` 的 `X` 在本卡人物中依次按 id、别名、名字和括号前的短名匹配，忽略大小写。id 优先，名字恰好等于另一个人物 id 时不会抢占该 id。没有匹配人物或该人物没有人设图时保持卡内原样。

`varId` 只允许 `[A-Za-z0-9_-]`，也是唯一进入样式文本的变量，消息正文无法借此注入样式或标记。

## 注入

插件注册的 display 处理器在卡片正则和 CBS 之前运行，在消息末尾追加一段：

```
{{#if {{greater_equal::{{chat_index}}::{{? {{lastmessageid}}}}}}}}<style>
.portrait[data-char="X" i]::after,.portrait[data-char^="X " i]::after{…}
</style>{{/}}
```

外层条件与卡内状态面板的显示条件相同，所以只在最新一条消息上保留，旧消息不堆积缩略图。`[data-char^="X "]` 兼容旧面板把姓名写在 `data-char` 里的写法。

规则用 `::after` 绝对定位铺满肖像位，层级高于卡内图片和占位图，背景 `cover`、顶部对齐，与卡内 `.char-img` 的裁切一致。Risu 渲染消息时照常给消息内样式加 `.chattext` 作用域和 `x-risu-` 类名前缀，规则只作用于本条消息内的面板。

处理器在插件启动时最先注册，早于状态读取和界面创建，因此 Risu 加载插件后渲染的第一条消息也能带上人设图。

## 刷新与容错

- 按资料版本号校验，10 秒内不重复请求。
- 服务不可达、响应异常或迟迟不回时沿用已取到的图，30 秒后再试；从未取到图时同样等待 30 秒。单次等待上限 2.5 秒，超时先按已有内容返回，迟到的结果留待下一条消息使用，不会让每条消息都等一遍。
- 角色卡可能被原地替换，所以同一位置的角色每隔一段时间会重新确认，换卡后不会沿用上一张卡的人设图。
- 未连接服务、群聊或没有 `varId` 的消息不做任何事；插件卸载时移除处理器。

## 不在范围

卡内名册侧栏的立绘（`xxx_basic_neutral`）以及面板的姓名、年龄、所属文字映射仍由卡自身维护。
