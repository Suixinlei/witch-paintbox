# 状态面板人设图

角色卡状态面板的肖像位和名册立绘读取卡内 `additionalAssets`，与画匣保存的人设图是两份；卡内缺资源条目、缺图或缺显示规则时只剩占位图，画匣换图后卡内也不会跟随。插件把画匣人设图盖到聊天里标了人物名的元素上，角色卡本身不改。

## 数据

`POST /v1/risu/portraits`（Risu 专用令牌）按 `cardId` 返回本卡带人设图的人物：`id`、`name`、`aliases`，以及各自缩略图的链接 `thumb` 和尺寸 `width`、`height`；服务里存有原图时另有原图链接 `full`。

链接按内容寻址：`/v1/risu/portrait/<cardId>/<人设图 SHA-256 前 32 位>.webp`，原图是同一地址加 `.full.<png|jpeg|webp>`。缩略图由服务按原图生成，长边不超过 640×960，WebP 编码，按原图内容缓存；无法解码的图跳过，不影响其余人物。页面自己按链接取图，请求不带令牌：地址本身就是凭证（128 位摘要），服务也只监听本机。原图只在读者放大时才取。

请求带上 `revision` 且资料未变时，服务只回 `{ revision, unchanged: true }`。`revision` 是 Risu 资料的整体版本，任一张卡或偏好保存后都会变化。不带 `links` 的旧版插件仍收到内嵌图片的数据包。

管理台「Risu 全局自动配图」中的「状态面板肖像取用画匣人设图」关闭后，接口返回空列表，消息里不再有指向图片的规则。已经发出的图片链接不受这个开关限制。

## 匹配

每个人物生成一条规则，列出状态栏可能用来指代这个名字的全部写法：先 `id`，再别名和括号前的短名。只有符合状态栏 `varId` 形状的名字（`[A-Za-z0-9_-]{1,64}`）会得到选择器；比较不分大小写。id 优先，名字恰好等于另一个人物 id 时不会抢占该 id。写进样式文本的只有这些名字和链接，消息正文无法借此注入样式或标记。

规则匹配的是聊天正文里带 `data-char` 的元素，属性值等于上述任一写法即命中。

## 注入

插件注册的 display 处理器在卡片正则和 CBS 之前运行，在消息末尾追加一段：

```
{{#if {{greater_equal::{{chat_index}}::{{? {{lastmessageid}}}}}}}}<style>
[data-char="X" i],[data-char="别名" i]{--wp-portrait:url("…webp");--wp-portrait-full:url("…full.png");--wp-ratio:0.684000}
…每个人物一条…
[data-char]{position:relative}
[data-char]::before{content:"";position:absolute;inset:0;z-index:3;pointer-events:none;background-image:var(--wp-portrait);background-size:cover;background-position:center top;background-repeat:no-repeat}
</style>{{/}}
```

外层条件与卡内状态面板的显示条件相同，所以只在最新一条消息上保留，旧消息不堆积样式块。Risu 渲染消息时照常给消息内样式加 `.chattext` 作用域和 `x-risu-` 类名前缀，规则只作用于本条消息里的元素。

## 槽位

带 `data-char` 的元素都会得到一层 `::before` 覆盖层，用该人物的缩略图从顶部铺满，层级高于卡内图片和占位图。卡在元素上用 `data-wp` 指定形状：

- 不写：状态面板的肖像位，圆角 7px。
- `face`：圆形裁切，用于对话气泡等小头像。
- `standing`：整身立绘。卡内自己的 `<img>` 没有图时按图片比例撑出高度，所以加载前占位尺寸就正确。
- `zoom`：固定定位、视口居中的一张大图，宽度不超过 96vw、高度不超过 92vh，外面一圈半透明金色细边；服务有原图时用原图，原图下载完成前只画出这圈金色底。

画匣里没有人设图的人物没有 `--wp-portrait`，覆盖层不画任何东西，卡内放什么就显示什么。

处理器在插件启动时最先注册，早于任务读取和界面创建，因此 Risu 加载插件后渲染的第一条消息也能带上人设图。

## 刷新与容错

- 按资料版本号校验，10 秒内不重复请求。
- 服务不可达、响应异常或迟迟不回时沿用已取到的样式，30 秒后再试；从未取到时同样等待 30 秒。单次等待上限 2.5 秒，超时先按已有内容返回，迟到的结果留待下一条消息使用，不会让每条消息都等一遍。
- 角色卡可能被原地替换，所以同一位置的角色每隔一段时间会重新确认，换卡后不会沿用上一张卡的人设图。
- 未连接服务时不做任何事；插件卸载时移除处理器。

## 不在范围

面板的姓名、年龄、所属文字映射，以及各槽位的布局和显隐，仍由卡自身维护。
