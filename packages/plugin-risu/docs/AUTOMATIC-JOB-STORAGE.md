# 任务存储

插件身份和 Risu 存储命名空间使用 `global-comfy-image`，显示名为魔女画匣。服务连接保存在 `paintbox-connection`，任务保存在 `automatic-jobs` 和 `automatic-context-<digest>`。

## 索引与快照

`automatic-jobs` 是 `{ version: 2, jobs: [...] }`。每个任务的 `pair`（本轮用户消息与助手回复）移入 `automatic-context-<digest>`，任务用 `contextRef` 引用；其余任务字段原样保留。上下文按完整内容去重，不按可能重复的消息 ID 合并，不修改正文或待点击计划。

2.6.0 之前的快照带有插件当时的本地设置，任务数组格式的旧索引则在每条记录里重复这些内容。读取时只用 `pair`：已有快照按原文件名继续引用，不重写也不复制；数组格式的旧索引在下一次保存时写出只含 `pair` 的新快照。

## 写入顺序与失败处理

上下文写入并通过原存储层读回验证后，才写索引；中途失败保留旧索引，多出的未引用上下文可供重试复用。索引写入确认失败时不发出绘图请求；保存操作只重试一次，不自动重发绘图请求。多个并发状态更新合并保存，所有等待者在最新状态保存成功后才继续。

启动恢复时保存失败只显示状态并暂缓恢复，不注销 UI 和消息处理器。不将存储故障冒充为模型错误。用户保持当前页面时内存任务仍保留，连接恢复后可再次操作，或重新打开页面恢复已持久化的任务。完全无法读取任务或上下文缺失时明确报错，不用空队列覆盖原数据。

## 恢复规则

- 规划于自动出图之前的待点击计划，刷新后仍等待点击，不会自动生图。
- 请求已发出但结果未保存的任务标记为失败，不自动重发。
- 提交生图后响应未保存的任务标记为“提交结果待确认”，不自动重试，避免重复生图。
- 已完成但未挂载的图片在启动时自动重新挂载；也可以在「配图」页点「为最新已完成回复自动配图」，只重新挂载，不重新生图。

## 保留

已结束的任务支撑同一回复上的重画、整楼重配和补图去重，所以不是画完就删：已结束任务超过 80 条时清理最旧的失败、已被替换或已挂载的任务，仍被整楼重配引用的批次除外。

插件只自用，不为旧版本保留回退兼容：2.6.0 之前的版本读不了 2.6.0 写出的快照。插件安装脚本不改写任务文件，迁移由插件本身通过 Risu 文件 API 执行。
